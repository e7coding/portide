# 部署中继 portide-relay

中继让不在同一局域网的设备也能互相连接：设备在线时和中继保持一条连接，对方连不上局域网时经中继转发。
中继只搬运加密后的数据，看得到公网 IP、路由 ID（设备公钥的哈希）、连接时间和字节数，还看得到每台设备的公钥本身（登记时要用它验证签名，路由 ID 就是从它算出来的），看不到文件、文件名、文本、设备名和设备圈成员名单。它不保存任何传输内容。
中继还会把它看到的每台设备的地址（通常是 NAT 之后的公网地址）告诉这台设备自己，设备再经已经加密的成员连接把它交给对方，用来尝试直连（打洞）；中继本身不参与打洞，也看不到设备之间交换的地址。

需要一台有公网 IP 的服务器（VPS、云主机都行），放行 **UDP 7443** 和 **TCP 7443**（TCP 是 UDP 被拦时的备用通道，见下文）。注意两层都要放行：

- 服务器自己的防火墙，例如 `sudo ufw allow 7443/udp` 和 `sudo ufw allow 7443/tcp`；
- 云服务商控制台里的安全组或防火墙规则：入站、来源 0.0.0.0/0、端口 7443，UDP 和 TCP 各一条。很多云主机默认只放行 TCP，所以 UDP 那条最容易漏；只放行其中一个也能用，但另一个被拦时就没有备用了。

UDP 和 TCP 都没放行时设备上显示"连接失败：中继没有回应（……放行了 UDP 7443 或 TCP 7443 端口）"。可以在服务器上执行 `sudo tcpdump -ni any port 7443`，再让设备连一次：一个包都看不到，就是云安全组那一层拦掉了。

## 方式一：直接运行二进制

```
tar xzf portide-relay-0.5.0-linux-amd64.tar.gz && cd portide-relay-0.5.0-linux-amd64
./portide-relay serve --public-addr 你的服务器IP或域名:7443
```

第一次运行时会生成中继密钥和第一个访问令牌，并打印一行：

```
portide relay add portide-relay://你的服务器IP:7443?fp=…&token=…
```

把这一整行复制到每台设备上执行。配置串只显示这一次，请妥善保存；丢了就用 `portide-relay token add` 再生成一个。

首次启动打印的"默认"令牌会留在 docker logs / journald 里：用 token add 生成自己命名的令牌并配置好设备之后，建议 token revoke 掉"默认"令牌。

中继的输出和日志默认按系统语言（`LANG`）显示，没有设置时（例如 systemd 服务、Docker 容器）用英文；要中文日志就加环境变量 `PORTIDE_LANG=zh`。

数据（密钥和令牌）默认保存在 `~/.config/portide-relay`，可以用 `--data` 或环境变量 `PORTIDE_RELAY_DATA` 指定。

长期运行建议用 systemd，例如 `/etc/systemd/system/portide-relay.service`。先创建一个固定的系统用户：

```
sudo useradd --system --home /var/lib/portide-relay --shell /usr/sbin/nologin portide-relay
```

```
[Unit]
Description=Portide relay
After=network-online.target

[Service]
ExecStart=/opt/portide-relay/portide-relay --data /var/lib/portide-relay serve --public-addr 你的服务器IP:7443
Restart=on-failure
User=portide-relay
StateDirectory=portide-relay

[Install]
WantedBy=multi-user.target
```

然后 `systemctl enable --now portide-relay`，用 `journalctl -u portide-relay` 查看首次启动打印的配置串。

管理令牌时也要用这个用户，例如：`sudo -u portide-relay /opt/portide-relay/portide-relay --data /var/lib/portide-relay token add …`。
不要用 root 直接执行 token 命令：生成的文件服务读不了，新设备会登记不上（中继日志会提示"无法读取令牌文件"）。

## 方式二：Docker

在解压出来的目录里（里面有 `portide-relay` 和 `Dockerfile`）：

```
docker build -t portide/relay .
docker run -d --name portide-relay --restart unless-stopped \
  -p 7443:7443/udp -p 7443:7443/tcp -v portide-relay:/data \
  -e PORTIDE_RELAY_ADDR=你的服务器IP:7443 portide/relay
docker logs portide-relay        # 查看首次启动打印的配置串
```

在容器里管理令牌：`docker exec portide-relay /portide-relay token list`。

## UDP 被拦时：TCP 备用通道

中继默认同时监听 UDP 7443 和 TCP 7443（`--tcp-listen` 默认和 `--listen` 相同，设为空字符串 `--tcp-listen ""` 则不监听 TCP）。设备先用 UDP 连中继；3 秒内没连上，就同时开始试 TCP，哪个先连上用哪个，不需要任何设置。公司网络、酒店 Wi-Fi、公共热点常常拦 UDP，云安全组也可能只放行了 TCP，这时设备会自动经 TCP 连中继。

- 经 TCP 连着时，状态显示"已连接（TCP）"（`portide relay`、桌面端和 iPhone 的"网络与中继"都一样）。
- TCP 比 UDP 慢：QUIC 跑在 TCP 里面，丢包后要等重传，延迟和吞吐都不如 UDP，所以大文件经 TCP 中继会明显慢一些。
- 设备每 10 分钟探测一次 UDP；UDP 恢复后日志记一行"中继 … 的 UDP 恢复了，改回 UDP"，自动改回 UDP。
- 经 TCP 连着时，这台中继看到的是 TCP 连接的来源地址，不能用来打洞，所以不会把它当作本机的外网地址交给对方；直连仍会照常尝试局域网地址、全局 IPv6 地址，以及对方（经 UDP 连着中继时）的外网地址，都连不上才一直经中继。
- TCP 对外的端口和 UDP 不同时（例如下面的 443），用 `--tcp-port` 写进配置串：`portide-relay serve --tcp-port 443`（首次启动打印的配置串）或 `portide-relay token add --tcp-port 443`，配置串里会多一个 `tcp=443`。不加时 TCP 端口和对外的 UDP 端口（`--public-addr` / `PORTIDE_RELAY_ADDR` 里的端口）相同，配置串里没有 `tcp=`；Docker 把容器的 7443 映射成别的端口（如 `-p 17443:7443/udp -p 17443:7443/tcp`）时也是这样，不用加。只有显式给了 `--tcp-listen` 又没给 `--tcp-port` 时，首次启动的配置串才用 `--tcp-listen` 的端口。

## 和网站共用 443

很多严格的网络只放行 443。服务器的 443 已经被网站占用时，可以用 nginx 的 `stream` 模块按 ALPN 分流：ALPN 是 `portide-relay-tcp/1` 的连接转给中继的 TCP 端口，其余的转给网站。需要 nginx 带 `stream` 和 `ssl_preread` 模块（`nginx -V` 里有 `--with-stream` 和 `--with-stream_ssl_preread_module`）。Ubuntu/Debian 的 nginx 里 `stream` 是动态模块（`nginx -V` 显示 `--with-stream=dynamic`），要先 `sudo apt install libnginx-mod-stream` 才能用。

在 `nginx.conf` 的最外层（和 `http {}` 并列）加：

```
stream {
    map $ssl_preread_alpn_protocols $upstream {
        ~\bportide-relay-tcp/1\b  portide_relay;
        default                  website;
    }

    upstream portide_relay { server 127.0.0.1:7443; }
    upstream website     { server 127.0.0.1:8443; }

    server {
        listen 443;
        ssl_preread on;
        proxy_pass $upstream;
    }
}
```

同时必须把网站原来的 `listen 443 ssl;` 挪到本机端口，写在 `http {}` 里的 server 块中，否则 443 被占用，nginx 起不来：

```
http {
    server {
        listen 127.0.0.1:8443 ssl;
        server_name 你的域名;
        # 证书等其余配置不变
    }
}
```

然后：

1. 中继照常监听 7443（TCP 只给 nginx 在本机转发用，可以改成 `--tcp-listen 127.0.0.1:7443`，对外不再暴露 TCP 7443）；
2. 生成配置串时带上 `--tcp-port 443`：`portide-relay token add --addr 你的域名:7443 --tcp-port 443`，配置串里就有 `tcp=443`；
3. 防火墙和安全组放行 TCP 443（UDP 仍然用 7443）；
4. `sudo nginx -t && sudo systemctl reload nginx`。

注意 `stream` 里转发的是原始 TCP，中继看到的来源地址都是 127.0.0.1；`--debug` 日志里的 IP 因此没有参考价值。

## 管理令牌

- `portide-relay token add --name 家里 --addr 你的服务器IP:7443`：生成一个新令牌，打印配置串；TCP 对外端口不同于 UDP 时加 `--tcp-port`。
- `portide-relay token list`：列出令牌（只显示编号、名称和生成时间，令牌本身不保存）。
- `portide-relay token revoke 编号`：吊销令牌，正在用它的设备几秒内会被断开。

令牌决定谁能使用这个中继。一个设备圈的设备共用一个令牌就行：配对新设备时，邀请方会把自己的中继配置自动带给新设备。

**丢了设备时**，按顺序执行：

1. 在另一台设备上 `portide devices rm` 把它移出设备圈；
2. 在中继上 `portide-relay token add` 生成一个新令牌，再 `portide-relay token revoke` 吊销旧令牌；
3. 在任意一台设备上执行 `portide relay add 新配置串`（同一个中继会更新令牌），会自动同步到设备圈里的其余设备；版本较旧的设备收不到同步，仍要逐台设置（`portide relay` 会列出这些设备）。

换令牌之前，被移除的设备仍能登记到中继：它能看出成员是否在线，能占用这个令牌的会话名额，还能经中继连上还没同步到移除记录的设备（这是设计方案 3.5 的已知局限，有了中继就不再限于同一局域网）。

## 多个中继

一个设备圈最多配 4 个中继，所有设备同时连接这些中继，不是主备：某个中继不可用时，经其余中继照常连通。设置保存在设备圈里并自动同步：在任意一台设备上 `portide relay add 配置串` / `portide relay rm 编号或地址`（只有一个中继时可以省略参数；桌面端、iPhone 上的"网络与中继"同理），其余设备几秒内跟着改。`portide relay` 列出每个中继各自的状态。

## 限制

- `--max-clients`：同时登记的设备数上限，默认 1000。
- `--max-sessions`：每个令牌同时进行的会话数上限，默认 64。
- `--session-rate 10MB`：每个会话每个方向每秒最多转发的字节数，默认不限。

## UDP 缓冲区

启动日志里如果有 `failed to sufficiently increase receive buffer size`，说明系统允许的 UDP 缓冲区太小，大文件经中继传输时会慢一些（不影响连接）。可以调大（需要 root，重启中继后生效）：

```
echo -e 'net.core.rmem_max=7500000\nnet.core.wmem_max=7500000' | sudo tee /etc/sysctl.d/90-portide-relay.conf
sudo sysctl --system
```

Docker 里运行时在宿主机上执行。

## 日志

默认只每 10 分钟记一次聚合计数（在线设备数、会话数、转发字节数），不记 IP 和路由 ID。排查问题时加 `--debug`，会记下每次登记和会话（含 IP 和路由 ID 前缀）。
