# Portide 实测：Windows + Linux（局域网与跨网络）

目标：两台电脑用 8 位配对码组成设备圈、互相看到在线，然后互传文件、文件夹和文本；对方离线时发送的内容排队，对方上线后自动送达；收发记录保存在本机的加密历史里；可以把丢失的设备移出设备圈；不在同一个网络时经中继互传。

> **版本说明（M4）**：新增 iOS 应用（在 Mac 上构建，见 `iOS.md`）和 macOS 桌面端（`.dmg`），实测见第 7d 节。协议和数据目录都没有变化，iPhone、Mac、Windows、Linux 可以在同一个设备圈里混用。
> 桌面端（M3b）：桌面端 `portide-desktop` 有了 Windows 版和安装包（Windows 安装程序 / zip，Linux `.deb` / tar.gz，说明见 `桌面端.md`），加入了传输页（暂停、继续、停止接收）、托盘、拖拽发送、系统通知和开机时启动，实测见第 7c 节。命令行新增 `portide queue pause|resume 任务号`。协议没有变化，桌面端设备和命令行设备可以在同一个设备圈里混用；"停止接收"对旧版本的发送方也有效（它会在下一次重试时被拒绝并停下）。
> 桌面端（M3a）：Linux 桌面端的基本功能见第 7b 节。
> 打洞（M2b）：这个版本在经中继连上之后会尝试打洞，打通了就自动改走直连（地址一列从"经中继"变成对方的公网或局域网地址），打不通（例如对称 NAT、运营商级 NAT）就继续经中继；经中继期间每 2 分钟重试一次，所以回到同一个局域网后不用重启也会改回直连。设备圈里的设备都要升级到这个版本才会打洞，有一方是旧版本时照常经中继。新旧版本混用的设备圈里，新版本设备向旧版本设备发起直连时，两者之间的连接可能断开一次、几秒内重新连上——这是预期行为。
> 中继（M2a）：加入了中继（`portide relay`，服务端是单独的 `portide-relay`，部署见包里的 `中继部署.md`）：两台设备不在同一个局域网时，经中继转发加密后的数据；局域网能连上时仍然直连。
> 中继只是可选项：不配置中继时和上一个版本完全一样。已有的数据目录、配对关系和历史都不受影响。升级后请不要再换回旧版本。
> 移除设备（M1b-4）：设备圈里的所有设备要先升级，再移除设备；移除时不在线的设备要靠上次连通的地址（或 `--peer`）、或者经中继连上一台已同步的设备才能更新。
> Windows 上请把新的 `portide.exe` 放在原来的位置覆盖旧文件：防火墙规则是按程序路径放行的，换了位置要重新允许。

## 0. 准备

- 两台电脑连在同一局域网，解压对应平台的包（`portide-m3a-windows-amd64.zip` / `portide-m3a-linux-amd64.tar.gz`）。
- **Windows 防火墙**：弹窗会出现在第一个用到网络的 `portide.exe` 命令上（通常是 `join` 或 `daemon`），勾选"专用网络"并允许；如果 Wi-Fi 被设成"公用网络"，也要勾上"公用网络"。没有弹窗也连不上时，用管理员 PowerShell 执行：
  `New-NetFirewallRule -DisplayName "Portide" -Direction Inbound -Protocol UDP -LocalPort 7443,5353 -Action Allow`
- quic-go 打印的"failed to sufficiently increase receive buffer size"是无害的，可以忽略。
- **Linux 防火墙**：如果启用了 ufw：`sudo ufw allow 7443/udp && sudo ufw allow 5353/udp`
- **私钥保存**：Windows 自动使用凭据管理器；Linux 有图形桌面时自动使用系统密钥库；
  无图形桌面时请设置 `export PORTIDE_KEYSTORE=file PORTIDE_PASSPHRASE='自己定一个口令'`（每次运行 portide 前都要设置同一个口令）

下文 Windows 命令写作 `portide.exe`，在 PowerShell 中需写成 `.\portide.exe`。

## 1. 组成设备圈（已经配对过的跳过这一步）

Linux 终端 1：`./portide init --name Linux台式机`，然后 `./portide daemon`；终端 2：`./portide pair`，记下配对码，例如 `4821-3907`。

Windows：
```
portide.exe init --name Windows笔记本
portide.exe join 4821-3907
portide.exe daemon
```
两台电脑分别运行 `portide devices`，对方状态应为"在线"。

`portide join` 在已经有设备圈的设备上也能用：本机是单机（只有自己）时，本机加入对方的设备圈；本机圈里已有其他设备、对方是单机时，由对方加入本机的设备圈；两边都有其他设备时是合并设备圈，需要加 `--merge` 表示同意（合并的实测步骤见 7g）。

## 2. 发送文件和文本

收到的文件默认保存在 `下载/Portide`（Windows 是 `C:\Users\<你>\Downloads\Portide`，Linux 是 `~/Downloads/Portide`）。
用 `portide config` 查看，`portide config save-dir <目录>` 修改。

Windows 发给 Linux（在新的 PowerShell 窗口，守护进程保持运行）：
```
portide.exe send Linux台式机 C:\Users\<你>\Pictures\某张照片.jpg
portide.exe send Linux台式机 --text "会议室改到 3 楼"
```
预期：Windows 显示进度和 `✓ 已发送`；Linux 守护进程窗口显示"已收到「Windows笔记本」发来的 …，保存在 …"，日志里只提示"收到一段文本"，内容要用 `portide history` 查看。

Linux 发给 Windows（文件夹）：
```
./portide send Windows笔记本 ~/文档/项目资料
```
预期：Windows 的 `Downloads\Portide\项目资料` 下目录结构和文件与 Linux 一致。

设备名可以换成 KeyID 前缀（`portide devices` 里显示的前几位）。

## 3. 离线发送队列

1. 停掉 Linux 的守护进程（Ctrl+C）。
2. Windows 上发送：`portide.exe send Linux台式机 C:\Users\<你>\Pictures\某张照片.jpg`
   预期：立即返回，显示"离线，已加入发送队列（任务 N）"。
3. `portide.exe queue` 能看到这个任务，状态为"排队中"。
4. 重新启动 Linux 的守护进程。预期：几秒内两边连上，Windows 守护进程日志显示"已向「Linux台式机」发送 …"，`portide.exe queue` 里状态变为"已发送"。

一次发给多台设备：`portide send 台式机,手机 文件`（每台一个任务，互不影响）。
取消排队的任务：`portide queue cancel 任务号`。排队任务默认保留 7 天，`portide config queue-days 天数` 可以修改。

## 4. 本地历史

1. 在两台电脑上分别运行 `portide history`：能看到前面发出（"→ 发给"）和收到（"← 来自"）的记录，最新的在前。
2. `portide history show 编号`：显示文本全文；收到的文件显示保存位置，发出的文件显示原文件位置。
3. `portide history --device Linux台式机` 只看和这台设备之间的记录；`-n 5` 只看最近 5 条。
4. `portide history rm 编号` 删除一条；`portide history clear` 清空（会让你输入 y 确认）。
5. `portide config history-days 30`：只保留最近 30 天，更早的由守护进程自动删除；`portide config history-days 0` 恢复永久保留。
6. 隐私检查（可选，Linux）：`grep -c 某个文件名 ~/.config/portide/portide.db` 应该是 0——数据库里只有密文。

## 5. 移除设备

只有两台电脑时，在 Linux 上另建一台"测试手机"（单独的数据目录和端口）来移除，不影响两台电脑之间的配对。

1. Linux 终端 2：`./portide pair`，记下配对码。Linux 终端 3：
   ```
   ./portide --data ~/portide-测试手机 init --name 测试手机
   ./portide --data ~/portide-测试手机 join 配对码 --addr 127.0.0.1:7443
   ./portide --data ~/portide-测试手机 daemon --listen :7445
   ```
   两台电脑上 `portide devices` 都能看到"测试手机"（Windows 上可能要等一会儿或显示离线，不影响后面的步骤）。
2. 停掉 Windows 的守护进程（Ctrl+C）：模拟移除时不在线的设备。
   注意：`devices rm` 需要守护进程在运行、并且至少有一台别的设备在线才能执行，否则会提示先确认设备圈是否已同步（或加 `--force` 强制执行）；
   这里只有 Linux 和测试手机在线，而测试手机正是要移除的目标——它自己在线不能说明设备圈已同步（被移除的设备不知道自己被移除了），
   所以这一步需要加 `--force`。
   **不要在两台设备上分别移除同一台设备**：没同步的设备再移除一次会让设备圈分裂（两边换成不同的发现密钥），只能重新配对。
3. Linux 终端 2：`./portide devices rm 测试手机 --force`，输入 y 确认。
   预期：显示"✓ 已把「测试手机」移出设备圈，并更换了发现密钥"；Linux 守护进程日志显示"「测试手机」已被移出设备圈，已断开连接"；
   之后测试手机每 3 秒重连一次，Linux 守护进程只提示一次"拒绝了来自 … 的连接：对方已不是本设备圈成员（10 分钟内不再重复提示）"。
4. 重新启动 Windows 的守护进程。预期：几秒内连上 Linux，日志依次显示"握手时同步了设备圈更新"和"从 Linux台式机 收到新的发现密钥"；`portide.exe devices` 里不再有"测试手机"。
5. 两台电脑互发一个文件和一段文本：照常送达。`portide history` 里和测试手机的旧记录仍然显示它的名字。
6. 不能移除本机：`./portide devices rm Linux台式机` 应提示"不能移除本机"。
7. 清理：停掉测试手机的守护进程，删除 `~/portide-测试手机`。被移除的设备要重新加入，也是先删掉它的数据目录，再重新配对。

## 6. 跨网络（中继）

需要一台有公网 IP 的服务器，按 `中继部署.md` 运行 `portide-relay`（放行 UDP 7443 和 TCP 7443），记下首次启动打印的 `portide relay add …` 那一行。

1. 两台电脑上分别执行那一行：`portide relay add portide-relay://…`。然后 `portide relay`：状态应为"已连接"（守护进程要在运行）。
   以后配对新设备时，邀请方会把中继配置自动带给新设备，不用再手动设置。
2. 让 Windows 换一个网络：例如连手机热点（Linux 留在原来的局域网）。几秒后两边 `portide devices` 里对方都是"在线"，地址一列显示"经中继（中继地址）"；
   守护进程日志里是"已连接 …（经中继）"。
3. 互发一个文件和一段文本：照常送达（速度取决于服务器带宽）；中断后能续传。
4. 离线排队经中继送达：停掉 Windows 的守护进程，在 Linux 上给它发一个文件（显示已排队）；再启动 Windows 的守护进程：几秒内经中继连上并自动送达。
5. 回到同一个局域网：不用重启，最多约 2 分钟后 `portide devices` 的地址一列重新显示局域网地址，日志里是"已切换到直连 …"（重启守护进程会更快：局域网能连上时不走中继）。
6. 中继拒绝时的提示：在一台设备上用一个错误的令牌执行 `portide relay add`（例如把 token 改掉几个字符），`portide relay` 应显示"连接失败：中继拒绝了登记…"；再改回正确的配置串。
   中继没有回应时的提示：把配置串里的端口改成一个没人监听的端口（例如 `:7444`）再 `portide relay add`，约 10 秒后 `portide relay` 应显示"连接失败：中继没有回应（……放行了 UDP 7444 端口）"；再改回正确的配置串。
7. `portide relay rm` 删除配置后（只有一个中继时可以省略参数；有几个时用 `portide relay rm 编号或地址`），`portide relay` 显示"没有配置中继"，跨网络时就连不上了（局域网照常）。
8. 移除设备后：`portide devices rm` 应提示"已配置中继：请换一个新令牌……"；按 `中继部署.md` 里"丢了设备时"的步骤换令牌，确认旧令牌吊销后被移除的设备再也登记不上中继。
9. **设置同步**：在一台设备上 `portide relay add` 一个中继，另一台设备几秒内执行 `portide relay` 应出现同一个中继（桌面端、iPhone 的"网络与中继"页同样出现，并显示"最后由「…」在 … 修改"）。
10. **换令牌只改一台**：在中继上换新令牌后，只在一台设备上 `portide relay add 新配置串`（同一个中继，会更新令牌），其余设备几秒内都换成新令牌并保持"已连接"。
11. **删除同步**：在一台设备上 `portide relay rm 编号或地址`（只有一个中继时可以省略参数；iPhone 上在列表里左滑删除），其余设备几秒内也不再有这个中继。
12. **旧版本**：设备圈里有一台 M6a 之前版本的设备时，`portide relay` 和设置页提示"…版本较旧，收不到中继设置的更改，需要在它上面手动设置"；在它上面手动设置后提示消失。
13. **边缘情况**：一台设备升级后一直没和设备圈里的其他设备连上过（它的中继设置还是升级时转过来的版本 0），如果这期间别的设备删掉了某个中继，它第一次连上时会把这个中继加回来，所有设备几秒内都又出现它。这时再删一次：之后它不会再回来（重启任意一台设备的守护进程再确认一次）。
    已经和其他设备同步过一次的设备不会这样：两台都从旧版本升级、配着同一个中继时，连上之后在一台上删掉它，另一台几秒内也删掉，重启后也不会回来。

## 6a. UDP 被拦（TCP 备用通道，M6b）

前提：第 6 节已经配好中继，服务器放行了 UDP 7443 和 TCP 7443（`sudo ufw allow 7443/tcp`，云安全组也要放行 TCP 7443）。下面的 `你的服务器IP` 换成实际地址。

1. 在 Linux 设备上拦掉去中继的 UDP：`sudo iptables -A OUTPUT -p udp --dport 7443 -j DROP`，然后重启守护进程（或 `portide relay rm` 后再 `portide relay add`）。
2. 几秒内（UDP 3 秒没回应后开始试 TCP）`portide relay` 应显示"已连接（TCP）"；日志里是已连接（TCP）。`portide devices` 里对方（另一网络的设备）在线，地址一列"经中继"。
3. 互发一个文件和一段文本：照常送达。记下这次的传输速度。
4. 经 TCP 连着时，把中继进程重启或在服务器上断开 TCP 连接：设备几秒内按退避重连，仍然是"已连接（TCP）"，对方重新在线。
5. 恢复：`sudo iptables -D OUTPUT -p udp --dport 7443 -j DROP`。10 分钟内（默认探测间隔）日志出现"中继 … 的 UDP 恢复了，改回 UDP"，状态变回"已连接"。
6. 速度记录：不拦 UDP 时传同一个大文件（例如 500 MB）记下用时，拦 UDP 经 TCP 再传一次记下用时，填在下表。TCP 预期明显慢于 UDP。

   | 通道 | 文件大小 | 用时 | 速度 |
   |---|---|---|---|
   | UDP | | | |
   | TCP | | | |

7. 都不通时的提示：同时拦 UDP 和 TCP（再加一条 `sudo iptables -A OUTPUT -p tcp --dport 7443 -j DROP`），约 10 秒后 `portide relay` 应显示"连接失败：中继没有回应（……放行了 UDP 7443 或 TCP 7443 端口）"；删掉两条规则后恢复。
8. 真实网络：在服务器上放行 7443/tcp，让设备连手机热点、公司网络或酒店 Wi-Fi（常拦 UDP），确认显示"已连接（TCP）"并能互传。
9. 可选：照 `中继部署.md` 的"和网站共用 443"配好 nginx，用 `token add --addr 你的域名:7443 --tcp-port 443` 生成配置串，在只放行 443 的网络里确认能连上，同时网站仍可访问。

## 6b. 打洞改走直连（M2b）

1. 按第 6 节第 2 步让两台电脑处在不同的网络（例如 Linux 在家里的宽带上，Windows 连手机热点），等两边都"经中继"连上。
2. 十几秒内看两边的守护进程日志：能打通时至少一边会出现"已切换到直连 …"，另一边可能是"已断开 …"紧接着"已连接 …（IP:端口）"；`portide devices` 的地址一列从"经中继"变成对方的公网地址（`IP:端口`）。
3. 打通之后互发一个大文件：速度不再受中继服务器带宽限制。如果切换正好发生在一次传输中途，这次传输会在直连上续传，内容完整（自动化测试覆盖了这种情况）。
4. 打不通时（手机热点、公司网络常见的对称 NAT 或运营商级 NAT）：日志里只有"已连接 …（经中继）"，一直经中继，收发照常——这是预期行为，记下两边各是什么网络即可。
5. 停掉中继服务器后，已经切换到直连的两台设备仍然连着，收发照常（直连不经过中继）。

## 6c. 多中继（M6a）

准备两个中继（R1、R2，两台服务器或同一台上不同端口），三台设备 A、B、C 在不同网络。

1. 在 A 上 `portide relay add` R1 的配置串，再 `portide relay add` R2 的：`portide relay` 列出两个，各自"已连接"；B、C 几秒内也出现这两个。
2. 把 R1 停掉：`portide relay` 里 R1 变为连接失败、R2 仍已连接；A、B、C 之间仍然能经 R2 互相连通、互发文件。
3. `portide devices` 的地址一列对经中继连上的设备显示"经中继（中继地址）"（iPhone 的设备详情同样）。
4. 添加第 5 个中继应报错（最多 4 个）。
5. 在 B 上 `portide relay rm 编号或地址` 删掉 R1（编号见 `portide relay` 的列表）：A、C 几秒内也只剩 R2。

## 7. 补充验证

| 场景 | 操作 | 预期 |
|---|---|---|
| 重名 | 把同一个文件发两次 | 第二次保存为 `名称 (1).扩展名`，不会覆盖 |
| 大文件续传 | 发一个几 GB 的文件，传到一半时在接收方关掉 Wi-Fi 约 1 分钟（超过 30 秒连接才会判定断开）再打开 | 发送方显示"连接中断，稍后自动续传…"；恢复后自动接着传（不是从头开始），最后显示 `✓ 已发送`，文件完整 |
| 取消 | 发大文件时在发送方按 Ctrl+C | 显示"已取消"；接收方日志显示"取消了发送"，`下载/Portide` 里没有残留文件 |
| 询问模式 | 接收方执行 `portide config receive 100MB`，再发一个超过 100 MB 的文件 | 接收方日志提示运行 `portide accept 编号`；`portide inbox` 能看到这条；`portide accept 编号` 后开始传输，`portide reject 编号` 则发送方显示"对方拒绝了" |
| 询问超时 | 询问模式下 2 分钟内不处理 | 发送方显示"对方没有在 2 分钟内确认" |
| 恢复自动接收 | `portide config receive auto` | 之后直接接收 |
| 排队期间改文件 | 对方离线时排队发送一个文件，然后修改这个文件，再让对方上线 | 对方收到的是修改后的内容 |
| 排队期间删文件 | 对方离线时排队，然后删掉文件，再让对方上线 | `portide queue` 显示失败："文件在发送前被移动或删除：…" |
| 发送中途关窗口 | 发大文件时直接关闭发送命令的窗口（不是 Ctrl+C） | 守护进程继续发送，`portide queue` 可以看到进度 |
| 同名文件 | 两台设备同时给第三台发同名文件 | 都能收到，其中一个改名为 `名称 (1).扩展名` |
| 中文和 emoji 文件名 | 发送 `测试 😀.txt` | 接收方文件名一致 |
| 特殊文件名 | 在 Linux 上建一个 `a:b?.txt` 发给 Windows | Windows 上保存为 `a_b_.txt` |

## 7b. 桌面端（M3a，只在 Linux 上）

Linux 上改用桌面端，Windows 照旧用命令行。先停掉 Linux 上的 `portide daemon`（桌面端自己就是守护进程）。

1. 换一个新的数据目录体验首次启动：`PORTIDE_HOME=~/portide-desktop-test ./portide-desktop`。欢迎页 →（没有系统密钥库时先设置口令）→ 填设备名 → 直接进入主界面（本机自动成为只有自己的设备圈，不再有"新建 / 加入"的选择）。
2. 设备 → 添加设备：显示 8 位配对码和倒计时。在 Windows 上用一个新的数据目录执行 `portide --data C:\portide-test join 配对码`（局域网里能自动找到；找不到时加 `--addr Linux的IP:7443`），再运行 `portide --data C:\portide-test daemon`。桌面端的对话框应显示"「…」已加入设备圈"，设备列表里对方"在线 · 局域网"。
3. 时间线：输入文本按 Enter 发送；点"文件"选几个文件、点"文件夹"选一个文件夹发送。Windows 上 `portide history` 能看到；中文输入法选字时按 Enter 只确认候选词，不会把半句话发出去。
4. 在 Windows 上 `portide send 设备名 --text …` 和发一个文件：桌面端时间线几秒内出现，文件卡片上"打开"用系统默认程序打开，"打开所在文件夹"打开文件管理器。
5. 设置 → 接收策略改成"都要确认"，Windows 再发一个文件：时间线顶部出现待确认卡片，点"接受"后收到。
6. 停掉 Windows 的守护进程，在桌面端给它发一段文本：时间线里是"排队中，等对方上线"，点"取消"后变成"已取消"。再发一段、然后启动 Windows 的守护进程：几秒内送达。
7. 设置页其余各项：更改保存位置、保留天数（填超出范围的数会提示并恢复）、外观切换深色。
8. 桌面端运行时在 Linux 上执行 `portide daemon`：提示守护进程已在运行（不会同时运行两个）；关掉桌面端、只运行 `portide daemon` 时再打开桌面端：提示"Portide 已经在运行"，停掉 `portide daemon` 后点"重试"进入主界面。
9. 复制文本 / 复制 KeyID 后在别处粘贴：时间线里文本气泡旁的"复制"、设置 → 基本里 KeyID 旁的"复制"，粘贴到文本编辑器里内容应一致。
10. 发一个包含很多文件的文件夹：时间线里折叠显示"等 N 个文件"（只列出前几个文件，后面一行是文件总数和总大小），点那一行的"打开所在文件夹"打开文件管理器。
11. 设备 → 移除 Windows 那台设备（之后可以删除 `C:\portide-test`）。

## 7c. 桌面端安装包、托盘、通知（M3b，Windows 和 Linux）

两台电脑都用桌面端。先停掉两边的 `portide daemon`；已经组成设备圈的继续用原来的数据目录即可（桌面端和命令行共用）。

1. **Windows 安装**：运行 `portide-desktop-m3b-windows-amd64-setup.exe`（SmartScreen 提示"未知发布者"时点"更多信息 → 仍要运行"），勾选"桌面快捷方式"。安装完成后开始菜单和桌面都有"Portide"，启动后能进入主界面；防火墙询问时允许"专用网络"。
2. **Linux 安装**：`sudo apt install ./portide-desktop-m3b-linux-amd64.deb`，应用菜单里出现带图标的"Portide"，从菜单启动。
3. **托盘**：两边都关闭窗口：程序缩到托盘，第一次会通知"Portide 仍在后台运行"（只提示一次）。托盘菜单的状态行显示"空闲"；左键单击托盘图标（或菜单"打开 Portide"）重新打开窗口。再次从开始菜单 / 应用菜单启动 Portide：不会开第二个，而是把已有窗口提到前面。
4. **通知**：把一边的窗口缩到托盘，从另一边发一段文本、再发一个文件：收到通知"来自「…」"。文件通知上点"打开"用默认程序打开，点"打开所在文件夹"打开文件管理器；点通知本身打开窗口并显示时间线。
5. **待确认**：接收方设置 → 接收策略改成"都要确认"，再发一个文件：通知上有"接受"和"拒绝"，点"接受"后收到；再发一个点"拒绝"，发送方收到通知"没有发给「…」"，原因"对方拒绝了"。测完把接收策略改回"自动接收"。
6. **传输页**：发一个几 GB 的文件。发送方的"传输"页显示进度条、速度和剩余时间，导航"传输"旁边是 1，托盘状态行是"1 个传输进行中"；接收方的"传输"页显示"来自「…」"和进度。在发送方点"暂停"：两边进度都停下，发送方显示"已暂停"，时间线里也是"已暂停"；点"继续"：从断点接着传（不是从头开始），最后文件完整。
7. **停止接收**：再发一个大文件，在接收方"传输"页点"停止接收"并确认：发送方的任务结束，时间线里显示"没有送达：对方停止了接收"，发送方收到发送失败的通知；接收方保存目录里没有残留文件，之后也不会再收到这个文件。
8. **拖拽发送**：把一个文件和一个文件夹从文件管理器拖到 Portide 窗口上：窗口出现遮罩"松开即发送给「…」"，松开后开始发送。在发送区取消所有选中的设备（设备圈里有两台以上其他设备时才能都不选），再拖：遮罩提示"先在时间线下方选择要发给哪台设备"，松开不发送。
9. **通知开关**：设置 → 通知与启动 → 关掉"系统通知"，再收一个文件：不再通知；测完打开。
10. **开机时启动**：打开"开机时启动"，注销后重新登录（或重启）：Portide 只出现在托盘里、不打开窗口，从另一台设备发来的文件照常收到。Linux 上用文件密钥库（启动时要输入口令）时，开机后会直接打开窗口要求输入口令。测完关掉"开机时启动"。
11. **没有托盘时（Linux，可选）**：在没有 AppIndicator 扩展的原版 GNOME 上运行，关闭窗口时程序直接退出。
12. **卸载**：Windows 上先从托盘菜单退出 Portide，再从"设置 → 应用"卸载：程序、快捷方式都删掉，`%APPDATA%\portide` 还在；重新安装后设备和历史都在。不先退出就卸载的话，卸载程序会提示"Portide 正在运行"并中止，退出后重新卸载即可。Linux 上 `sudo apt remove portide-desktop`，`~/.config/portide` 还在。
13. **命令行**：`portide queue` 能看到桌面端暂停的任务（"已暂停"），`portide queue resume 任务号` 让它继续。

## 7d. iPhone 和 Mac（M4）

先在 Mac 上按 `iOS.md` 构建：`bash scripts/build-ios.sh` 能跑完（模拟器单元测试通过），再用 Xcode 装到 iPhone。macOS 桌面端：`bash scripts/build-desktop.sh mac`，打开生成的 `.dmg` 安装。

**iPhone**（和一台 Windows 或 Linux 桌面端一起测，两边连同一个 Wi-Fi）：
1. **首次启动**：没有"设置口令"这一步；填设备名 →"输入配对码加入"，在桌面端"设备 → 添加设备"里拿到配对码，地址留空：能在局域网里自动找到对方并加入。允许"本地网络"权限。两边的设备列表里对方都"在线 · 局域网"。（不允许"本地网络"时找不到对方，这时在地址里填桌面端的 `IP:7443` 也能加入。）
2. **收文本和文件**：桌面端发一段文本、一张照片、一个视频、一个 PDF：iPhone 时间线里出现；照片和视频同时出现在"照片"App 里（第一次会询问"添加照片"权限）；点文件用"快速查看"打开，右上角可以分享；"文件"App 的"我的 iPhone › Portide"里能看到所有收到的文件。
3. **发**：在 iPhone 上输入文本发送；点"+"从相册选几张照片和一个视频发送；再从"文件"选一个文件夹发送。桌面端都收到，内容一致。
4. **通知**：Portide 在前台时，桌面端发来内容会弹出横幅"来自「…」"。把接收策略改成"都要确认"，再发一个：通知上有"接受"和"拒绝"（长按通知），点"接受"后收到。测完改回"自动接收"。
5. **传输页和暂停**：从桌面端给 iPhone 发一个 1 GB 以上的文件：iPhone"传输"页显示进度、速度和剩余时间，标签上有数字；在桌面端暂停再继续，传完文件完整（可以在 Mac 上用 `shasum` 比对）。
6. **退到后台**：再发一个大文件，传到一半时把 Portide 切到后台（回到主屏幕）：再传一小会儿后停下（发送方显示"中断，稍后重试"）；重新打开 Portide：几秒内重新连上，从断点继续传完，不是从头开始。
7. **离线排队**：彻底退出 iPhone 上的 Portide（上滑关掉），在桌面端给它发一段文本：显示"排队中"；打开 iPhone 上的 Portide：几秒内收到。
8. **跨网络**：桌面端和 iPhone 都配置同一个中继（iPhone：设置 → 中继，粘贴配置串），iPhone 关掉 Wi-Fi 用蜂窝网络：设备列表里显示"经中继"或"直连"，能互发文本和照片。
9. **移除**：在桌面端把 iPhone 移出设备圈，iPhone 上的设备列表随之更新（或者在 iPhone 上移除另一台设备）。

**M0 里留到真机上的验证项**（结果请一起发回来）：
- QUIC 和 SQLite 能在 iPhone 上正常运行（上面的步骤能走通即可）；
- Bonjour 和桌面端的 mDNS 能互相发现（第 1 步不填地址能找到对方；iPhone 上 Portide 在前台时，桌面端设备列表里它"在线 · 局域网"）；
- 大文件速度：第 5 步的文件大小和耗时（BLAKE3 校验在 iPhone 上的速度会体现在这里）。

**Mac**：
1. 打开 `.dmg`，把 Portide 拖到"应用程序"，在"隐私与安全性"里允许打开；允许"本地网络"和"通知"。
2. 首次启动：欢迎页 → 设备名 → 主界面。然后和现有的设备配对：一台在"添加设备"里选"显示配对码"，另一台选"输入配对码"，哪边显示都可以；只有自己一台设备的那一方会加入另一方的设备圈。
3. 按第 7c 节的第 3–10 步测托盘（菜单栏图标）、通知、传输页、拖拽和开机时启动。

## 7e. 桌面端新界面（M3c，Windows 和 Linux）

两台电脑都装新版本（`portide-desktop-m3c-…`）。**两边都升级之后**才能改名，所以先把两边都装好。

1. **三栏和快捷键**：左边图标栏、中间列表、右边内容；Ctrl+1 / 2 / 3 / 4 切换时间线、传输、设备、设置，Ctrl+K 打开搜索。深色模式（设置 › 外观 › 深色）下各页都能看清。
2. **会话**：从另一台发一段带链接的文字、一个 PDF、一个装了几张照片的文件夹、一张 PNG。对应设备的会话里：文字里的链接能点开浏览器；PDF 是红色图标的文件卡片；文件夹是一张卡片"文件夹名 · N 个文件 · 大小"，下面有缩略图和"+N"，点"展开文件列表"能看到文件；PNG 显示缩略图。同一分钟里连着收到的几条只在第一条上显示时间。
3. **发送状态**：发一段文字，下面显示"已送达"。关掉对方的 Portide 再发：显示"等「…」上线后送达"，列表里这台设备显示"1 条等待对方上线"；点"撤回"能撤回。
4. **拖到某台设备上**：把一个文件拖到左边列表里另一台设备那一行上（不用先点开它）：这一行出现虚线框和"松开发给「…」"，松开后发给它。拖到对话区：整块出现遮罩"松开发给「…」"。
5. **粘贴图片**：截一张图（Windows：Win+Shift+S；Linux：PrtSc 复制到剪贴板），在输入框里 Ctrl+V：直接发出，文件名是"截图 日期 时间.png"。
6. **搜索**：Ctrl+K，输入前面发过的一个词或文件名：结果里标出设备；回车跳到那一条，这一条短暂高亮。
7. **右键**：在一条消息上右键 →"删除这条记录"：本机的记录消失，对方那边还在，收到的文件还在。
8. **传输页**：发一个几 GB 的文件：顶部"1 个正在传输"，图标栏"传输"上是 1；这时关掉对方再发一段文字，排队的那条不算进图标栏的数字（M3b 里排队的也算）。点"全部暂停"：都停下，按钮变成"全部继续"。最下面"最近完成"里点一条能跳到时间线。
9. **改名**：设备 → 点另一台设备 → 名字旁的铅笔，改成新名字回车：几秒内两边的列表、会话、通知里都是新名字。在自己这台的 设置 › 通用 里也能改本机名字。命令行 `portide devices` 显示的也是新名字。
10. **设备图标**：设备详情 › 设备图标里换成"手机"：只在本机的列表里变，另一台不受影响。
11. **添加设备**：设备 →"添加设备"：配对码分两组大字显示，"复制"能复制；Esc 关闭对话框后配对码失效。重新打开，用一台新设备（或新的数据目录）加入：对话框变成"「…」已加入设备圈"，"给它发消息"直接打开它的会话。
12. **设置**：分成通用、接收、通知与启动、网络与中继、存储与历史、外观、关于；每改一项底部都提示"已保存"。接收 › 保存位置显示成"下载 › Portide"这样，"打开"能打开这个文件夹。网络与中继 › 本机地址列出本机的局域网地址。
13. **托盘**：托盘菜单第一行是"空闲 · 1 台设备在线"之类；传输时多一行文件名和百分比，托盘图标右下角出现绿点。菜单"发送文件…"选一个文件：窗口打开，文件发给当前会话的设备（在"全部设备"里时发给发送区选中的设备）。"暂停全部"能暂停正在发的。
14. **窗口位置**：把窗口拖到屏幕右边、改小一点，退出（托盘 → 退出）再打开：在原来的位置和大小。设置 › 通用里关掉"关闭窗口时缩到托盘"后，点窗口的关闭按钮就退出。
15. **端口被占用**：先用命令行在同一台电脑上开一个占用 7443 的守护进程（换个数据目录：`portide --data portide-port init --name x`，再 `portide --data portide-port daemon`），再启动桌面端（先退出原来的）：显示"端口被占用"页，有"重试"和"换一个端口启动"，"详细信息"里是原始错误。点"换一个端口启动"：进入主界面，设置 › 网络与中继显示"自动选择"和实际端口；另一台设备照样能连上（局域网自动发现）。测完把端口改回"默认 7443"，重启桌面端，停掉命令行的守护进程，删除 `portide-port` 目录。
16. **首次启动**（可选，用一个新的数据目录：把环境变量 `PORTIDE_HOME` 设成一个空目录再启动桌面端）：欢迎页 → 设备名（默认"用户名 的笔记本 / 台式机"，有一键选项）→ 直接进入主界面（没有"新建 / 加入"卡片）。再测配对的三种情况：一台"显示配对码"、另一台"输入配对码"（输入框自动分成两组数字）；任意一方单机时，单机的一方加入另一方的设备圈，与谁显示配对码无关；两边的设备圈里都还有其他设备时进入"合并设备圈"（见 7g）。

## 7f. iOS 新界面（iPhone 和 iPad）

先在 Mac 上用 `bash scripts/build-ios.sh` 装好新版本（版本 0.5.0），再和一台桌面端组成设备圈。浅色、深色（iOS 的"设置 › 显示与亮度"，或 Portide 的 设置 › 外观）各看一遍。

1. **首次启动**（可选：删掉应用重新安装）：欢迎页（Portide 标志、三个卖点）→ 设备名默认"我的 iPhone"，下面有一键选项 → 直接进入主界面（没有"新建 / 加入"卡片）。配对在设备 →"添加设备"里：一台"显示配对码"，另一台"输入配对码"（输入框自动分成两组数字，"找不到对方？"里可以填地址）；单机的一方加入另一方的设备圈；两边都有其他设备时进入"合并设备圈"（见 7g）。
2. **会话列表**："全部设备"在第一行，下面每台设备一行（头像、在线点、最后一条、时间）；对方离线时有排队内容显示"N 条等待对方上线"。
3. **会话**：从桌面端发一段带链接的文字、一个 PDF、一个装了几张照片的文件夹、一张 PNG：日期分隔、时间只在第一条上、链接能点开 Safari、PDF 是红色图标的卡片、文件夹卡片有缩略图和"+N"、"展开文件列表"能看到文件；点文件用快速查看打开。
4. **发送**：在某台设备的会话里发文字、照片、文件；截一张图后在"＋"菜单里选"粘贴图片"直接发出。发出的显示"已送达"；关掉对方再发显示"等「…」上线后送达"，可以撤回。
5. **长按消息**：复制、分享、删除这条记录（对方那边还在）。
6. **搜索**：在会话列表顶部搜索一个词或文件名：结果里匹配部分高亮、标出设备；点一条跳到那一条并短暂高亮。
7. **传输页**：发一个大文件：顶部"1 个正在传输"，标签上的角标是 1；排队的不算进角标。"全部暂停 / 全部继续"可用。"最近完成"点一条能跳到会话。
8. **设备**：点一台设备：改名（铅笔）后几秒内桌面端也是新名字；换设备图标只在 iPhone 上变；"发消息"打开它的会话；复制设备指纹。
9. **添加设备**：配对码分两组大字、复制、倒计时、三步说明；用另一台设备加入后变成"「…」已加入设备圈"，"给它发消息"打开它的会话。
10. **设置**：七个分类，每改一项顶部提示"已保存"；接收方式、大文件阈值、自动存相册、历史保留、离线队列有效期、中继、本机地址（点一下复制）、外观。
11. **iPad**：横屏时会话、设备、设置三个标签页都是左边列表、右边内容；竖屏时和 iPhone 一样点进去。

## 7g. 合并设备圈（M5b）

准备两个设备圈：A 圈三台（A1、A2、A3），B 圈两台（B1、B2），各自先配好；可以在 Linux 上用不同数据目录和端口模拟。要测"需要升级"，再准备一台旧版本（M5a 或更早）的设备放进 A 圈。

1. **合并，在线的跟过来**：A 圈里 A2 开着，让 A3 保持离线（停掉它的守护进程）。在 B1 上"显示配对码"，A1 上"输入配对码"：输入框上方说明两个设备圈会合并、点名 A2 和 A3，点"加入"。预期：A1 的结果页写"已合并，设备圈里现在有 5 台设备"，下面是 A2、A3 各一行"「…」还没跟过来，它和这里任意一台合并过来的设备连上时会自动跟过来（30 天内）"（A2 在线，结果页出来时它也还没来得及跟过来）。
2. **确认 A2 跟过来**：在 A1 的设备页看 A2。预期：几秒内 A2 的"等待合并"消失，不需要任何操作；B1、B2、A1、A2 的设备页互相显示在线，A3 仍显示"等待合并"。
3. **离线的跟过来**：A3 的设备页（A1 上）显示"等待合并"。启动 A3 的守护进程。预期：几秒内 A3 跟过来，A1、A2、B1、B2、A3 都在同一个圈里，"等待合并"消失；五台设备互发一个文件都能送达。
4. **旧版本**：A 圈里放一台旧版本设备，合并后它在设备页显示"需要升级"；升级并启动后自动跟过来。
5. **失败重试**：合并过程中断开网络再恢复，重新配一次应能成功，B 圈里不会出现重复的设备。
6. **到期**（可选，改系统时间或等 30 天）：没有跟过来的设备显示"没有跟过来"，可以移出设备圈。
7. **命令行**：`portide devices` 对这些设备显示"等待合并 / 需要升级 / 没有跟过来 / 去了别的设备圈"。

8. **两个圈用不同中继**：A 圈只配 R1，B 圈只配 R2；让 B1 配对 A1 合并后，合并后的圈里有 R1 和 R2 两个中继；A 圈里还没跟过来的设备即使只能连上 R1，也能跟过来。

## 7h. 共享到 Portide（M7，iPhone）

这是 M7 的 Swift 代码第一次在 Mac 上编译，之前从没编译过：如果 `build-ios.sh` 编译报错，请把完整输出发回来。

准备：Mac 上运行 `bash scripts/build-ios.sh`（或 `bash scripts/build-ios.sh project` 再用 Xcode 打开 `ios/Portide.xcodeproj`），装到 iPhone。共享扩展需要 App Group `group.<包标识>`（默认 `group.org.portide.app`）：用 Xcode 自动签名时第一次构建会自动注册（免费账号也可以），装真机需要设置 `PORTIDE_TEAM_ID`。用免费 Apple 账号签名时，装到 iPhone 上的 Portide 和共享扩展 7 天后过期、打不开，需要重新构建安装。先和一台桌面端组成设备圈。

1. **照片和视频**：相册选 3 张照片和 1 个视频 → 共享 → Portide：Portide 打开，弹出"发送到…"，列出 4 项；选一台电脑发送，电脑收到原文件名的照片和视频。
2. **大文件**：在"文件"App 选一个 1 GB 以上的文件 → 共享 → Portide：扩展显示进度，不崩溃；发送成功。
3. **网页**：Safari 分享网页 → Portide：对方收到链接文本。
4. **文字**：备忘录分享一段文字 → Portide：对方收到这段文字。
5. **对方离线**：对方离线时分享：提示已加入发送队列，对方上线后收到。
6. **取消**：在"发送到…"里点取消：发件箱里没有残留的副本（设置 → 存储里的占用不增加）。
7. **兜底**：分享时 Portide 没被打开的话（例如以后的系统禁止了扩展打开 App），扩展提示"已交给 Portide，打开 Portide 就能继续发送"；手动打开 Portide 后自动弹出"发送到…"。
8. **首次安装**：首次安装、还没完成向导时分享：完成向导后弹出"发送到…"。
9. **Portide 里开着别的面板时**：在 Portide 里打开一个收到的文件预览（或相册选择器）时，从相册分享到 Portide：关闭预览后弹出"发送到…"（或回到 Portide 时弹出），不丢失。
