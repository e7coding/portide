# Portide 桌面端（Linux、Windows 和 macOS）

`portide-desktop` 是带界面的 Portide：时间线（收发文本和文件）、传输（进行中的发送和接收）、设备（添加、移除）、设置。它自己就是守护进程：关闭窗口后缩到托盘，继续在后台保持和设备圈的连接、收发文件；从托盘菜单"退出"才真正退出。

和命令行 `portide` 完全互通：协议、数据目录、配对关系都一样，可以和只用命令行的设备组成同一个设备圈。

## 安装

下面的文件名以 0.5.0 为例，换成实际下载的版本号。

### Windows（64 位，Windows 10 / 11）

- 安装程序 `portide-desktop-0.5.0-windows-amd64-setup.exe`：装到"程序文件\Portide"，建开始菜单快捷方式（桌面快捷方式可选）。安装程序没有代码签名，Windows 会提示"未知发布者"（SmartScreen），点"更多信息 → 仍要运行"。
- 免安装版 `portide-desktop-0.5.0-windows-amd64.zip`：解压后运行 `portide-desktop.exe`。
- 需要 Microsoft Edge WebView2 运行时（Windows 11 和更新过的 Windows 10 自带）；安装程序检查到没有时会提示下载地址。
- 第一次运行时 Windows 防火墙会询问是否允许 Portide 访问网络：请允许"专用网络"，不然局域网里的设备连不上这台电脑。
- 卸载：先从托盘菜单退出 Portide（卸载程序会检测到 exe 还在运行并提示），再从设置 → 应用 → Portide → 卸载。卸载不删除数据目录（`%APPDATA%\portide`），重新安装后设备身份、设备圈和历史都还在；不再使用的话手动删除这个目录。
- 升级：先从托盘菜单退出 Portide，再运行新的安装程序。

### Linux（x86-64）

- Ubuntu / Debian：`sudo apt install ./portide-desktop-0.5.0-linux-amd64.deb`。程序装在 `/opt/portide`，应用菜单里出现"Portide"。卸载：`sudo apt remove portide-desktop`（同样不删除数据目录 `~/.config/portide`）。
- 其他发行版：解压 `portide-desktop-0.5.0-linux-amd64.tar.gz`，运行里面的 `portide-desktop`。需要 GTK3 和 WebKitGTK 4.1（Fedora：`sudo dnf install gtk3 webkit2gtk4.1`）。
- 托盘：KDE、Ubuntu 自带的桌面直接可用；原版 GNOME 需要装 AppIndicator 扩展（`gnome-shell-extension-appindicator`）。没有托盘时关闭窗口就退出，避免程序在后台却找不到。

### macOS（Apple 芯片或 Intel，macOS 11 以上）

- 打开 `portide-desktop-0.5.0-macos-arm64.dmg`（Intel 的 Mac 是 `…-amd64.dmg`），把 `Portide.app` 拖到"应用程序"（以前装过 `Portide.app` 的，先把它删掉）。
- 程序没有 Apple 签名和公证：第一次打开时系统会提示"无法验证开发者"，到"系统设置 › 隐私与安全性"里点"仍要打开"。
- 第一次打开时允许"本地网络"（找到局域网里的其他设备）和"通知"。
- 托盘图标在屏幕顶部的菜单栏里。
- 数据目录：`~/Library/Application Support/portide`。

## 第一次启动

1. 欢迎页点"开始使用"。
2. 没有可用的系统密钥库（例如 Linux 上没有登录 GNOME 钥匙圈）时，先设置一个口令，以后每次启动都要输入；有系统密钥库时（Windows 总是有）跳过这一步。
3. 起设备名：默认是"用户名 的笔记本 / 台式机"，下面有几个一键选项，以后也可以改。

第一次启动会自动建好一个只有这台设备的设备圈，不需要选"新建"或"加入"。要和别的设备组成设备圈，在两台设备的"添加设备"里，一台选"显示配对码"，另一台选"输入配对码"并输入它（命令行设备用 `portide pair` / `portide join`）。局域网里找不到对方时，点"找不到对方？"填对方的地址（对方 设置 › 网络与中继 › 本机地址里有）。

只有自己一台设备的一方会加入另一方的设备圈，谁输入都一样；设备名、历史记录和设置都保留。两边都有其他设备时，设备圈会合并：输入配对码的一方所在的设备圈整个并入显示配对码的一方的圈，两边所有设备都在新圈里，所以建议在设备多的一边显示配对码。本机圈里有其他设备时，输入框上方会先说明合并会发生什么，并点名这个设备圈里会一起并过去的设备，点"加入"才开始；完成后结果页写"已合并，设备圈里现在有 N 台设备"，并逐台写明还没跟过来的设备（"还没跟过来"或"版本太旧，需要先升级"）。还没跟过来的设备（比如当时不在线）在设备页显示"等待合并"：它和任意一台已经合并过来的设备连上（局域网、已知地址，或者用同一个中继）后会自动跟过来，不需要任何操作，30 天内有效。旧版本的设备显示"需要升级"，升级后同样会自动跟过来；30 天后仍没有跟过来的显示"没有跟过来"，可以把它移出设备圈，或者再和它配一次对。已经去了别的设备圈的设备显示"去了别的设备圈"：原来设备圈里的部分设备合并到了别的设备圈，把那个设备圈和这里再合并一次即可。命令行里 `portide join` 在两边都有其他设备时需要 `--merge`，`portide devices` 对这些设备显示同样的状态。

## 日常使用

窗口分三栏：最左边是图标栏（时间线、传输、设备，最下面是设置），中间是列表，右边是内容。快捷键：Ctrl+1 / 2 / 3 / 4 切换这四页，Ctrl+K 搜索，Esc 关闭对话框。

- **时间线**：每台设备一个会话，第一个"全部设备"是所有设备混在一起的时间线。在某台设备的会话里发的内容就是发给它；在"全部设备"里先在发送区选设备（可以多选）。
- **发送**：输入文字按 Enter（Shift+Enter 换行），或点回形针选文件、点文件夹按钮选文件夹；截图之类的图片可以在输入框里 Ctrl+V 直接粘贴发送。
- **拖放**：把文件或文件夹拖到对话区，发给当前会话的设备；拖到左边列表里的某台设备上，直接发给它（离线的会在它上线后送达）。
- **消息**：链接可以点，用浏览器打开；文件卡片上有"打开"和"在文件夹中显示"；右键一条消息可以复制、删除这条记录（只删本机的记录，不删文件）。没送达的可以"重发"。
- **搜索**：Ctrl+K 或列表上面的搜索框，搜文字内容和文件名，点结果跳到那一条。
- **传输页**：顶部是正在传输和等待中的数量，"全部暂停 / 全部继续"。进行中的发送可以暂停、继续、取消（暂停的任务不会过期，继续后从断点续传）；正在接收的可以停止，对方会收到"对方停止了接收"，已收到的部分会删除。下面是最近完成的 5 条。图标栏"传输"上的数字只算正在传输的，排队等对方上线的不算。
- **设备**：空列表里有"显示配对码"和"输入配对码"两个按钮，局域网里有设备正在等待配对时会提示"附近有设备正在等待配对"。设备圈合并后还没跟过来的设备显示"等待合并"（见"第一次启动"）。点一台设备看详情：改名（铅笔）、换图标（只影响本机）、设备指纹、移出设备圈。改名会同步给设备圈里的所有设备；有设备还没升级到这个版本时不能改名，会写明是哪台。
- **托盘**：托盘菜单里有状态（正在传输几个、几台设备在线）、"发送文件…"（选完文件后发给当前会话的设备）、"暂停全部 / 全部继续"。设置 › 通用里可以改成关闭窗口就退出。
- **系统通知**：收到文件或文本、发送失败、有待确认的接收时通知。收到文件的通知上有"打开"和"打开所在文件夹"，待确认的有"接受"和"拒绝"；点通知本身打开窗口并显示时间线。设置 → 通知与启动里可以关掉。
- **开机时启动**：设置 → 通知与启动里打开后，登录时 Portide 只在托盘里启动，不打开窗口；需要输入口令时照样打开窗口。
- **中继**：设置 › 网络与中继里可以添加多个中继，中继设置会同步到设备圈里的所有设备。
- **界面语言**：中文和英文。默认跟随系统语言（系统是中文时用中文，其余用英文），在设置 › 外观 › 语言里可以固定成一种；托盘菜单和系统通知跟着一起换。
- **检查更新**：每天向 GitHub 查一次有没有新版本，有的话设置图标上出现小圆点，设置 › 关于里可以下载；装新版覆盖旧版即可，数据和设置都保留，不会自动更新。GitHub 能看到本机的 IP 地址，不发送其他信息。在设置 › 关于里关掉"自动检查更新"即可停止。自己从源码编译的版本不检查。

## 和命令行一起用

- 数据目录和命令行相同：Linux 默认 `~/.config/portide`，Windows 默认 `%APPDATA%\portide`，macOS 默认 `~/Library/Application Support/portide`，用 `PORTIDE_HOME` 环境变量改。
- 桌面端运行时，同一个数据目录**不能再运行 `portide daemon`**。反过来，`portide daemon` 在运行时打开桌面端，会提示"Portide 已经在运行"，停掉 `portide daemon` 后点"重试"即可。
- 桌面端运行时，`portide send`、`portide devices`、`portide history`、`portide queue pause|resume 任务号` 等命令照常可用，界面在 3 秒内显示它们的结果。
- 同一个数据目录只能运行一个桌面端，再次启动会把已有的窗口提到前面（包括缩在托盘里的）。

## 已知限制

- 两个设备圈使用不同的中继时，跨网络的迁移不支持：还没跟过来的设备要和合并过来的设备在局域网里或用已知地址直连才能跟过来。
- 输错配对码后马上重新输入，偶尔会提示配对失败（邀请方还在处理上一次尝试），等几秒再输入即可。
- 设备圈里有设备还没升级到这个版本时不能改名（旧版本不认识改名记录）。
- 端口被占用（例如另一个 Portide 在运行）时，启动页上可以"换一个端口启动"；设置 › 网络与中继里也能改端口。手动填过本机地址的设备需要改成新端口。
- 不能往托盘图标上拖文件，只能拖到窗口上。
- macOS 版本还没有 Apple 签名和公证，Windows 安装包没有代码签名（见"安装"）。

## 从源码构建（开发者）

需要 Go 1.26、Node.js 22 和 pnpm。Linux 包另外需要开发包 `sudo apt install libgtk-3-dev libwebkit2gtk-4.1-dev` 和 `dpkg-deb`；Windows 包在 Linux 上交叉编译（不需要 cgo），另外需要 NSIS（`makensis`）；macOS 包只能在 Mac 上打（需要 Xcode 命令行工具）。

```bash
bash scripts/build-desktop.sh                 # 两个平台都打：dist/ 下的 .deb、tar.gz、setup.exe、zip
bash scripts/build-desktop.sh linux          # 只打 Linux
bash scripts/build-desktop.sh windows        # 只打 Windows
bash scripts/build-desktop.sh mac            # 在 Mac 上：dist/ 下的 Portide.app 和 .dmg
```

版本号只写在 `core/version/VERSION` 一处：安装包文件名、Windows 文件版本、macOS 和 iOS 的版本号、`portide --version` 和"关于"页都从它来，发版时只改这个文件。构建号（macOS / iOS 的 CFBundleVersion）默认是 git 提交数，可以用 `PORTIDE_BUILD` 指定。

Wails v3 beta 在 Linux 上默认用 GTK4，Portide 用 GTK3，所以 Linux 上的 Go 构建都要加 `-tags gtk3`。

图标由 `desktop/build/gen-icons.go` 画出（`cd desktop && go run build/gen-icons.go`），改了图形之后重新生成。

界面调用的 Go 方法有自动生成的 TypeScript 绑定（`desktop/frontend/bindings/`，不要手改）。改了 `app/`（桌面端和 iOS 共用的服务层）或 `desktop/platform.go` 里导出的方法之后重新生成：

```bash
cd desktop && go run -tags gtk3 github.com/wailsapp/wails/v3/cmd/wails3 generate bindings -ts -clean -f "-tags gtk3" -d frontend/bindings
```

在浏览器里调试界面：Wails 的 server 模式把应用作为本机网页服务运行（系统文件对话框、托盘、通知在这个模式下不可用）：

```bash
cd desktop/frontend && pnpm build && cd .. && go build -tags "server gtk3" -o /tmp/portide-desktop-server .
PORTIDE_HOME=/tmp/portide-ui WAILS_SERVER_PORT=28480 /tmp/portide-desktop-server   # 然后打开 http://localhost:28480
```
